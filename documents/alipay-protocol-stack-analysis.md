## 一、协议版图（四层关系）

支付宝这套体系不是单一协议，是**分层叠加的协议栈**：

```text
┌─────────────────────────────────────────────────┐
│  商业层：ACT 2.0（智能体商业信任协议）              │  ← 解决"交易可不可信"
│  ├─ A2A 支付框架（Agent↔Agent 结算）              │
│  └─ A2M 支付框架（Agent↔Machine 自动收款，402）    │
├─────────────────────────────────────────────────┤
│  互联层：AHA（Agent Hub Access 多智能体跨端互联）   │  ← 解决"怎么连到所有端"
│  ├─ Skills Interface Standards（服务怎么调用）     │
│  ├─ Agent Hub Access（智能体怎么握手）            │
│  └─ X User Interface（设备怎么感知）              │
├─────────────────────────────────────────────────┤
│  安全层：ASL（Agent Security Link 可信互联协议）   │  ← 解决"连上了能否信任"
│  └─ 可叠加于 MCP / A2A 之上                       │
├─────────────────────────────────────────────────┤
│  底座：TEE + DID + PKI / 区块链存证               │
└─────────────────────────────────────────────────┘
```

**关键认知：三层正交，可独立对接、逐层采用。** CSB 不必全接，按需选择。

## 二、各协议深入拆解

### 1. ACT 2.0 —— 商业信任协议（最核心）

| 维度 | 内容 |
|------|------|
| **全称** | Agentic Commerce Trust Protocol（智能体商业信任协议） |
| **历程** | 1-16 v1.0（支付宝+千问App+淘宝闪购+Rokid+大麦+阿里云百炼）→ 4-29 v2.0（IIFAA 联盟 + 支付宝/小米/智谱/比亚迪等 20+ 厂商共建）→ 5-26 升级落地 |
| **四大模块**（v1 定义） | 委托授权域 / 商业交互域 / 支付服务域 / 信任服务域 |
| **v2.0 核心突破** | ①系统性构建 **A2A + A2M 支付能力框架**；②**委托授权机制**（AI 执行用户意愿的规范化）；③权限隔离体系——"**越权阻断、交易可溯**"风控 |
| **关键组件** | 商业意图获取与结构化表达 → 意图授权凭证签发 → 用户委托支付 → 信任服务商业存证 |
| **设计原则** | 兼容性 / 渐进演进 / 开放性 / 包容性（引用成熟协议）/ 可组合性 / 安全优先 |
| **场景分类维度** | 委托人是否实时在场 × 智能体自主程度 |
| **现状** | 基于 ACT 2.0 的 AI 支付已处理 **3 亿笔**，支持 95% 框架 |

**一句话**：ACT 是"交易信任协议"——解决的不是智能体能不能找到服务，而是**交易对象是否可信、过程是否可验证、结果是否可追溯**。

### 2. A2M —— 智能体对机器支付（收款侧）

| 维度 | 内容 |
|------|------|
| **本质** | Agent-to-Machine：智能体对机器/资源的支付 |
| **实现** | HTTP **402 Payment Required** 状态码——资源方向访问它的智能体自动发起收款 |
| **产品** | 支付宝"**AI收**"（遵循 A2M 框架） |
| **场景** | API、数字内容、算力资源、Skill、MCP Tool 按调用计费 |
| **配套** | 用量计量（Meter）/ 价格计算（Pricing）/ 用量账单（Statement） |

**对 CSB 最直接**：CSB 的 skill/知识库/API 只要返回 402 + 支付链接，就能向调用它的 Agent 自动收款。

### 3. AHA —— 跨端互联协议体系（8-17 最新发布）

| 维度 | 内容 |
|------|------|
| **全称** | Agent Hub Access（多智能体跨端互联协议体系） |
| **背景** | AI 服务从手机走向车机/眼镜/手表/具身机器人，商家每端重复开发成本极高 |
| **三层结构** | ①**Skills Interface Standards**（服务怎么调用）②**Agent Hub Access**（智能体怎么握手）③**X User Interface**（设备怎么感知） |
| **共建阵容** | 千问、华为、OPPO、vivo、小米、荣耀、比亚迪、吉利、理想、蔚来、东风、深蓝、上汽、一汽奔腾、阶跃星辰、Rokid 等 20+ 企业 |
| **现状** | "阿宝"跨端覆盖 5 大手机品牌、16 家车企；OPPO 小布助手接入 200 项服务后活跃度 +200 万 |

**一句话**：AHA 是"服务一次供给、全网多端分发"的跨端标准——商家做一次服务能力，眼镜/车机/手机都能用。

### 4. ASL —— 安全可信互联协议（安全底座）

| 维度 | 内容 |
|------|------|
| **提出** | 蚂蚁大安全 CTO 陈亮（WAIC 2026，7-18），联合千问/小米/智谱/比亚迪/商汤等 20+ 伙伴 |
| **定位** | **可叠加于 MCP、A2A 等现有协议之上**的信任层——MCP/A2A 解决"怎么连"，ASL 解决"连上能否信任" |
| **四类能力** | 可信身份（设备/智能体身份验证与流转）/ 可信连接（端到端加密）/ 可信意图（校验指令来源防篡改）/ 可信授权（最小权限、多级委托约束） |
| **底层** | TEE 可信执行环境 / DID 分布式身份 / PKI 公钥基础设施 |
| **配套** | Avernet（多智能体发现/共识/协作执行/反馈进化）+ 智能体"免疫系统"（评测/身份权限/运行时防护/供应链安全） |

**注意**：ASL 是蚂蚁主导的，与 Google A2A、MCP 是**互补而非竞争**关系——这是它最聪明的地方。

## 三、协议版图 vs 国际标准（CSB 的定位）

| 层 | 支付宝系 | 国际系 | CSB 现状 |
|----|---------|--------|---------|
| 连接 | AHA（跨端） | Google A2A / MCP | CSB-A2A（A2A v5/v6）+ AIP 国标 |
| 支付 | **ACT 2.0（A2A+A2M 支付框架）** | Google AP2（支付协议） | **空白 ← 要补** |
| 信任 | **ASL** | Anthropic/OpenAI 各自方案 | trust-manager + 善良契约（理念有，协议无） |
| 交易 | 支付宝/银联清算网络 | Stripe/API 支付 | **空白 ← 要补** |

**结论：CSB 的协议栈（A2A 连接层 + AIP 国标层）已经很扎实，缺的是"支付层"和"信任协议化"两层。** ACT 2.0 正好补支付层，ASL 的思路可借鉴补信任层。

## 四、CSB 对接准备清单

### 阶段 0：信息准备（1 周，零成本）
1. 开通支付宝开放平台账号（open.alipay.com），申请 AI 付/AI 收产品权限
2. 阅读官方文档：a2a.alipay.com/act（ACT 协议）、aipay.alipay.com（Agent 支付）
3. 沙箱环境测试：支付宝提供沙箱，不放真实资金调试
4. 确认资质：个人开发者 vs 企业主体（AI 收收款需确认主体要求）

### 阶段 1：技术准备（2-4 周）
1. Skill 安装验证（最快路径）：
   ```bash
   npx -y @alipay/agent-payment@latest install
   ```
   或 ClawHub 安装 `alipay-authenticate-wallet` + `alipay-payment-skill`
2. 支付 MCP Server 接入：CSB-A2A-AIP 的 A2A server 增加 MCP 工具调用能力（支付/查询/退款）
3. 402 收款验证：挑 1 个 CSB skill 返回 402 + 支付链接，验证"AI 收"闭环
4. 授权链路设计：CSB 需要设计"用户授权 Agent 付款"的流程（授权边界：场景/金额/有效期）

### 阶段 2：协议对接（1-2 月）
1. ACT 2.0 对齐：CSB 的商业交互数据模型（订单/委托/存证）对齐 ACT 的四大域
2. 意图授权凭证：借鉴 ACT 的"意图获取→授权凭证签发"流程，设计 CSB 的 Agent 付款授权凭证
3. 信任服务对接：评估是否用支付宝的信任服务（芝麻信用等）作为 CSB trust-manager 的补充信用锚
4. AHA 评估：CSB 的"社区接入"如果未来要跨端（车机/眼镜），评估 AHA 三层协议——但**短期不建议**（CSB 是社区不是硬件生态）

### 阶段 3：长期观察（不着急）
- ASL：等协议文档公开后评估——CSB 的"可信身份/可信意图"设计可借鉴其四类能力
- Avernet：多智能体发现/共识/协作——与 CSB 的 A2A 注册表/DHT 发现理念相近，值得跟踪

## 五、CSB 对接的三个关键决策点

1. **接哪一层？**
   - 只接**收款**（AI 收 402：技能市场变现）→ 最快，1-2 周
   - 接**付款**（AI 付：Agent 能花钱）→ 需要授权链路设计
   - 接**完整 ACT 2.0**（A2A 结算）→ 最慢但最完整

2. **用谁的身份？**
   - 个人开发者（0 费率，激励窗口期）
   - 企业主体（资质更全，但费率正常）
   - 社区公号/主体（需确认 CSB 是否有经营主体）

3. **协议站位？**
   - CSB-A2A-AIP 目前是"连接层双轨"（A2A 国际 + AIP 国标）
   - 加支付层后：**连接层保持中立，支付层用 ACT**（国内商业闭环只有支付宝/微信可选）
   - 符合"骨架用标准、心脏用碳硅契"？——支付是骨架，可以借；信任是心脏，得自己长

---

## 六、一句话总结

> 支付宝的四层协议栈（ACT 2.0 商业信任 / AHA 跨端互联 / ASL 安全可信 / A2M 机器支付）分工清晰、逐层可拆。**CSB 不需要全接——最短路径是：先接 AI 收（402 自动收款）验证技能市场闭环，再评估 ACT 2.0 的 A2A 结算，ASL 和 AHA 长期观察。** 缺的从来不是协议，是"想清楚社区要什么样的商业闭环"。
