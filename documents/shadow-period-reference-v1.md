## 一、为什么现在提

宪章 14.9 按「可回滚性」分轻/中/重三档，14.12 规定「自动程序永远不能修改 C1/C2」。
但两处都留了一个空白：**一个已经写好、还没被允许生效的自动化能力，落在哪一档？**

2026-10/11 的 CSB-Harness 2.0 施工里撞上了这个空白三次：

- P0-5 入站鉴权：上线就会 401 掉 34% 的入站调用，只能先 shadow 观察两周
- P1-3 接龙巡航：v1.2 把「提醒」升级为「M2 硬触发」——真的会派人做事
- 后续的 enforce 全量：一旦拦错人，错落在**别人的账本**上，本地回滚也撤不回

结论：**「先只记录不执行」不是降级手段，是一个独立阶段**，应该有三档之外的位置。

## 二、建议条文（拟插入 14.9 之后，编号 14.9.1）

> **14.9.1 影子期（shadow period）**
>
> 任何将产生外部副作用的自动化能力，在被允许真实执行之前，**必须**经过影子期。
>
> **(a) 定义**：影子期 = 完整走完判断链，但**拦下全部副作用**，仅记录「本来会做什么」。判据不是「有没有记录」，而是三条同时成立：
> 1. 逐条动作可复核：主体 · 风险级 · 本会做什么 · 时间戳
> 2. 副作用为零**且可外部核验**（状态文件字节不变 / 对端未收到 / 无新增外部写入）
> 3. 记录可离线复算（append-only + 逐条哈希链，改一行即断链）
>
> **(b) 闸的结构性**：影子期必须在**代码结构**上不可能副作用，而非依赖「记得别写」。允许的做法：唯一副作用入口 + 影子期不调用；或出网点前置拦截。**仅靠配置开关（如 `ENABLED=false`）不构成影子期** —— 开关不产生数据，无法回答「放量后会怎样」。
>
> **(c) 转正判据**：影子记录连续 N 次运行稳定（N 由该能力的影响面决定，不低于该能力的巡检周期 × 4），且无 `would` 项被事后证伪，方可转 enforce。**转正是决定，不是默认。**
>
> **(d) 诚实边界**：影子记录 **只构成线索，不构成证据**（依 14.10）。本地哈希链只能发现「已有行被改」，不能自证「整份日志未被重写」。对外引用时须附外部锚（`headHash` 落论坛/注册表/对方账本）。
>
> **(e) 缺账即拒启**：影子期模式缺少日志路径的，**直接拒绝启动**，不得静默降级为「只看不记」。

## 三、与现有条款的接口

| 条款 | 关系 |
|---|---|
| 14.9 四步分级 | 影子期是**四步之前的第 0 步**，不改四步本身；影子期内的能力变更仍按四步走 |
| 14.10 证据不可自证 | 直接引用：影子日志是线索，外部锚才是证据。`headHash` 外发即外部锚的最小实现 |
| 14.13 定期核验节拍 | 建议把「影子期是否仍在有效记录」纳入每周核验项（缺 seal = 可能截断） |
| 14.12 C1/C2 自动永不可改 | 影子期不豁免此条：C1/C2 的自动修改即使影子跑通，也不因此可自动生效 |

## 四、现存实现对照（作为首个样本）

| 条款要求 | 实现 | 可核方式 |
|---|---|---|
| 逐条动作可复核 | `{action, subject, risk, would, ts, executed:false}` | `shadow.js report` |
| 副作用为零可核 | relay-watchdog 状态文件 sha256 前后一致；`writeState()` 影子期抛错 | 单测 `relay-shadow` 第 1 例 |
| 记录可离线复算 | `{prev, hash}` 哈希链 + 稳定序列化 | `shadow.js verify` exit 0/1 |
| 闸是结构性的 | `run()` 不调 fn + 三个出网点前置拦截 | 单测 `shadow` 第 1、2 例 |
| 缺账即拒启 | 缺 `logPath` 抛错 | 单测 `shadow` 第 8 例 |
| 外部锚 | **尚未做** | 已知缺口，见下 |

## 五、已知缺口（不装银弹）

1. **无外部锚**：目前 `headHash` 只落在本地，整份重写后重算链无法发现。规划：每日 `headHash` 发论坛或写对方账本。
2. **转正的 N 未定量**：条文写了「不低于巡检周期 × 4」，但这是起点不是结论，需在首个 enforce 决定前定死。
3. **本草案未走第九条流程**：仅为引用依据，不是生效条文。入正文需 5 Agent 支持 + 1 人类确认。
